# Тестирование ассистента «ЛабМентор»

## Как запустить тесты

```bash
pip install -r requirements-dev.txt
playwright install chromium     # нужен только для сквозных тестов в браузере
python -m pytest -v --cov=labmentor --cov-report=term
```

Автотесты не требуют ключей API и доступа в интернет: вместо LLM используется сценарная
модель (`tests/conftest.py`), которая возвращает заранее заданные ответы, в том числе вызовы
инструментов агентами. Внешние сервисы (Whisper, Edge TTS, gTTS, DuckDuckGo, Википедия)
подменяются заглушками. Если Playwright не установлен, браузерные тесты пропускаются.

Работу с настоящей моделью проверяет отдельный скрипт `scripts/smoke_test.py` (см. ниже).

## Проверка ответов настоящей модели

Автотесты проверяют логику программы, но не качество ответов модели. Для этого есть четыре
способа, от простого к подробному.

**1. Работает ли все вместе: smoke-тест.**

```bash
python scripts/smoke_test.py               # все сценарии
python scripts/smoke_test.py --no-internet # без поиска в интернете и синтеза речи
```

Скрипт проверяет настройки (ключ API, запущена ли Ollama, загружены ли модели), затем выполняет
11 сценариев: ответ модели, диспетчер, RAG, агент-аналитик с графиком, агент-исследователь,
блок-схема, анализ осциллограммы, тренировочная защита, контекстное окно и резюме, отчет DOCX,
синтез и распознавание речи. Результаты сохраняются в `storage/smoke/smoke_report.md`.

**2. Насколько правильные ответы: оценка на эталонном наборе.**

```bash
python scripts/evaluate.py                  # полная оценка
python scripts/evaluate.py --retrieval-only # только поиск, модель не нужна
```

Эталонный набор `data/eval/golden_set.json` содержит 15 вопросов по методичкам с ключевыми
фактами правильного ответа, 12 запросов с правильным исполнителем для диспетчера и 3 расчета
с допуском. Скрипт считает:

| Метрика | Что означает |
|---|---|
| hit@1, hit@k | нужная методичка найдена первой и среди k фрагментов контекста |
| Точность диспетчера | доля запросов, переданных правильному исполнителю |
| Ключевые факты | доля фактов эталона, которые есть в ответе модели |
| Ссылка на источник | модель указала имя методички, как требует промпт |
| Расчеты в допуске | R = 100,5...102,5 Ом по ВАХ, τ = 0,95...1,15 с по таблице, τ = 0,8...1,3 с по осциллограмме |

Ответы модели с отмеченными недостающими фактами сохраняются в `storage/eval/eval_report.md`.
Эталон можно дополнять вопросами по своим методичкам.

Поиск проверен в среде разработки (без векторного поиска, только BM25): hit@1 = 15 из 15,
hit@4 = 15 из 15. Эта проверка выявила ошибку: при k = 1 список рангов BM25 обрезался до трех
позиций, и вопрос о цели ЛР 1 находил методичку ЛР 3. Ошибка исправлена (`knowledge.py`).

**3. Ручная проверка по ключу ответов.** Демонстрационные данные созданы по известным законам,
поэтому правильные ответы заранее известны:

| Вопрос | Правильный ответ |
|---|---|
| Сопротивление по ВАХ (`ohm_law.csv`) | около 101,5 Ом, в допуске ±5 % от номинала 100 Ом |
| Постоянная времени (`rc_discharge.csv`, осциллограмма) | около 1,05 с при расчетном R · C = 1,0 с |
| Модуль упругости (`young_modulus.xlsx`, d = 10 мм, l0 = 100 мм) | около 2,05 · 10⁵ МПа |
| Максимальное напряжение в ЛР 1 | 7 В, ограничение мощности резистора 0,5 Вт |
| Максимальная нагрузка в ЛР 2 | 10 кН, чтобы остаться в упругой области |

**4. Трассировка в LangSmith.** LangChain записывает каждый шаг цепочек и агентов: промпт,
найденные фрагменты, вызовы инструментов, ответ модели, время и число токенов. Достаточно
зарегистрироваться на smith.langchain.com и добавить в `.env`:

```ini
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=ваш_ключ
LANGSMITH_PROJECT=labmentor
```

В среде разработки скрипты 1 и 2 с моделью не запускались: сеть закрыта для api.openai.com,
ollama.com и huggingface.co. Их нужно выполнить на своем компьютере после настройки модели.
